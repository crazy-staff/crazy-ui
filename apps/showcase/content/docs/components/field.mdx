## Usage

```tsx
import { Field } from '@crazy-staff/ui';
```

```tsx
<Field label="Hero name" description="Shown in the trainer menu.">
  <Field.Control placeholder="Nameless hero" />
</Field>
```

## Examples

### Compound parts

`Field.Root`, `Field.Label`, `Field.Control`, `Field.Description` and `Field.Error` let you order and style each
part yourself. The short form above renders the same thing.

### Required

`required` on the field marks the label; `required` on the control makes it required. With
`validationMode="onBlur"`, the error shows when the user leaves the empty field. `errorMatch="valueMissing"`
picks which validity error the message is for.

<ComponentPreview name="field/required" />

### Custom validation

`validate` gets the value and returns an error message (or `null`). With `validationMode="onChange"` it runs on
every keystroke; an empty `Field.Error` shows the returned message.

<ComponentPreview name="field/validation" />

### Invalid from the server

Set `invalid` yourself (for example after the server rejects a value) and `errorMatch` to always show the error.

## Accessibility

- `Field.Label` is linked to the control, and `Field.Description` and `Field.Error` are added to its
  `aria-describedby`. You don't need ids.
- When the field is invalid, the control gets `aria-invalid` and the error is announced with the description.
- The required asterisk is decorative; the control's `required` attribute is what screen readers announce.
