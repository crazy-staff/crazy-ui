## Examples

### Dialog

`Command.Dialog` puts the palette in a modal near the top of the screen and closes it after an item runs.
Open it with a `trigger`, or control `open` yourself — here with **Ctrl/Cmd + J** (Ctrl/Cmd + K opens this
site's search, which is itself a `Command.Dialog`). Pass `handle` to open it from a detached
`<Dialog.Trigger handle>` elsewhere in the app.

<ComponentPreview name="command/dialog" />

### Breadcrumbs and descriptions

Items in the short form take `breadcrumbs` (a path line above the label) and a `description` under it.
The typed words are highlighted in the label and the description.

<ComponentPreview name="command/rich-items" />

### Search with filters

A docs or app search built from the parts: `Command.JumpItem` puts "Jump to …" first when the query starts
a page title, rows stack `Command.ItemBreadcrumbs` above a `Command.Highlight`ed title, and the footer holds
`Command.Filters` with `Command.Filter` menus and `Command.Hint` keys. Pass `filter={null}` and filter the
items yourself. "Clear filters" has its own slot at the end of the row: it shows only when a filter is set,
keeps its place when hidden and never wraps, so the layout doesn't move. The search of this site (Ctrl/Cmd + K)
is built the same way on Fumadocs' search client.

<ComponentPreview name="command/search" />

### Loading and empty

For results that come from a server, show `Command.Loading` while waiting and `Command.Empty` when nothing
came back. The short form takes `loading` and `loadingText`.

<ComponentPreview name="command/loading" />

### Compound parts

Use `Command.Root` with your own items and render the rows yourself. `Command.Footer` holds hints, a count
or filters.

## Accessibility

- Built on Base UI Autocomplete in inline mode: the input is a `combobox` controlling an always-visible
  `listbox`; the first match is highlighted.
- **Arrow keys** move, **Enter** runs the highlighted item, **Esc** closes the dialog.
- Items also match their `keywords`. Shortcuts are hints only (`aria-hidden`); wire the keys yourself.
- The dialog is named by `title` (default "Command palette"); the input by `aria-label`
  (default "Search commands").
- `Command.Loading` is a `role="status"` region, so screen readers hear "Searching…".
- Filters are menu buttons named "Section: All" etc. with a radio group inside; the filter row is a
  `group` named "Filters". The hidden "Clear filters" button is `disabled` and out of the tab order.
- Highlights are `<mark>` elements, so the text reads the same with or without them.
